# APPEAR-001: conditional appearance in the builder

Decisions and verified DevExpress facts are on the card (#1707). Every slice goes test first, red checked.

## 1. Core (no DevExpress)

- `AppearanceSpec(TypeName, Rules)`, `AppearanceRuleSpec(Id, TargetKind, Targets, Criteria, Context, FontColor,
  BackColor, FontStyle, Enabled, Visibility, Priority)`; enums `AppearanceTargetKind { Items, Layout }`,
  `[Flags] AppearanceFontStyle`, `AppearanceVisibility { Show, Hide, ShowEmptySpace }`. Colours are strings (JSON).
- `ISupportAppearanceRules { static abstract AppearanceSpec? BuildAppearanceRules(); }`.
- `AppearanceBuilder<T>.Create().Rule(id, r => r.When(..).On(x => ..).OnLayout("Header").FontColor(..)
  .BackColor(..).FontStyle(..).Disable().Visibility(..).Priority(..).InListView().InDetailView().InView(id)).Build()`.
- `LayoutSpecChecks.Validate(AppearanceSpec)`: blank or repeated id, no or blank target, both kinds of target,
  no appearance value, a colour that does not parse.
- `CSharpLayoutPrinter.PrintAppearance`, `PrintClass(..., appearance)` adds the interface and method.
  `LayoutSpecs` gains an optional `Appearance` half.

## 2. Add-on `XafLayoutBuilder.Appearance`

- Module requires `XafLayoutBuilderModule` and `ConditionalAppearanceModule`.
- `AppearanceRegistry.Register<T>` / `RegisterJson<T>` and a resolver (registry first, then the interface).
- `AppearanceRulesUpdater : ModelNodesGeneratorUpdater<AppearanceRulesModelNodesGenerator>`: checks first
  (member targets exist, XLB006 id taken by an [Appearance] rule), then adds the rules.
- Startup check on SetupComplete: touches each spec'd class's AppearanceRules, XLB007 layout target on no
  DetailView layout of the class, XLB008 criteria that does not parse.

## 3. Export

- A hook in `LayoutCodePrinter` the add-on fills: model rules without an `[Appearance]` attribute become the
  spec; attribute rules are named in the leading comment. JSON export carries the half too.

## 4. Sample, gate, docs

- `Order.Layout.cs` rules (a list cell rule and a layout group rule), host registers the add-on module.
- Gate: the styled cell and group caption, screenshot; the Order round trip compares the rules too.
- SKILL.md, README, api-notes, CHANGELOG, CLAUDE.md (project list, pack command), how-it-works.
